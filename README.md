# HyperOS 图标补全器

面向 KernelSU WebUI 的 HyperOS/MIUI 主题图标补全模块。

## 安装

1. 下载 Release 中的模块 ZIP。
2. 在 KernelSU 管理器中从本地安装。
3. 重启手机后，从模块详情页打开 WebUI。

仓库根目录即模块目录。打包时应确保 `module.prop` 位于 ZIP 根目录，不要额外套一层文件夹。

模块通过仓库根目录的 `update.json` 向 KernelSU 提供更新信息。发布新版本时，需要同步更新：

- `module.prop` 中的 `version` 和 `versionCode`
- `update.json` 中的 `version`、`versionCode` 和 `zipUrl`
- `CHANGELOG.md`

GitHub Release 标签使用 `v版本号`，附件名称使用 `HyperOS-Icon-Patcher-v版本号.zip`。

## Windows 打包

直接双击仓库根目录的 `pack-module.bat`。脚本会自动读取 `module.prop` 版本号，
在仓库根目录的 `output` 文件夹中生成 `HyperOS-Icon-Patcher-v版本号.zip`，并输出文件大小和 SHA-256。

也可以在命令行中指定输出目录：

```bat
pack-module.bat E:\my\release
```

需要在打包前重新编译 Android ARM64 辅助工具时使用：

```bat
pack-module.bat -RebuildHelper
```

## 功能

- 将首页功能分为“修补图标”和“图标缝合”两类，原有修补组流程保持独立
- 选择只读源主题和目标主题，将源主题中已安装应用的图标新增或覆盖到目标主题
- 新增图标默认选择，覆盖已有图标需要手动确认；支持双列预览、筛选、搜索和批量选择
- 主题间缝合按 drawable 密度优先匹配源图标，并复用目标写入的原子替换与异常回滚
- 仅列出用户安装应用，展示应用名称及当前图标
- 缓存应用名称并分批读取信息，图标进入可视区域后再加载
- 为应用选择 PNG，自动以包名命名
- 仅接受 PNG 输入，并校验 PNG 文件头
- 自动调整新增图标尺寸，确保单个文件不超过 50KB
- 仅支持 Android ARM64，使用模块内置 `hipzip-arm64` 在手机端索引并快速生成主题
- 扫描主题商店 `.data/content/icons/*.mrc` 图标主题
- 按相同 UUID 匹配 `meta/icons/*.mrm`，优先读取 JSON 的 `titles.zh_CN`，并兼容 `description.xml`
- 选择主题时只读取 ZIP 中央目录索引，不向 WebUI 传输完整 MRC
- 使用临时回滚文件安全修改商店图标源，再由主题商店正式应用
- 校验错误通过 Toast 和日志同时提示
- 设备命令超时后自动恢复按钮，避免界面永久卡在“处理中”
- 写入前校验主题完整性，写入后校验哈希，异常时自动回滚
- 创建、重命名、复制和删除独立修补组，修补组不再绑定主题文件名
- 修补组内以应用包名作为唯一键，重复添加时直接覆盖
- 修补组名称最多 40 个前端字符／120 个 UTF-8 字节，不允许重名；最多 50 个修补组、每组 500 个图标
- 模块持久数据设置 256MB 上限，并在复制、合并、回滚和写入前检查真实可用空间
- 支持“仅补全缺失图标”和“覆盖同名图标”两种修补模式
- “覆盖同名图标”执行前显示主题、修补组和图标数量确认
- 缺失补全没有可写条目时直接提示“无需修补”，不生成或覆盖 MRC
- 修补组数据采用原子切换，避免保存中断导致图标丢失
- 修补成功后立即删除临时回滚文件，不长期保存整份主题备份
- 覆盖安装或更新模块时保留修补组
- 卸载模块时清除新旧持久化数据及主题目录中的模块临时文件
- 跟随系统、浅色和深色三种 WebUI 外观
- 进入 WebUI 时自动扫描主题，选择主题后自动读取手机端中央目录索引
- 从主题商店返回 WebUI 后自动重新扫描，重名主题显示时间和文件标识
- 修补组管理按可视区域懒加载 PNG 预览，批量删除通过后端原子完成
- WebUI 启动时恢复中断的原子目录并清理上传、合并、回滚及主题写入孤儿文件
- 主题名称解析结果按文件大小和修改时间做小型缓存，减少重复扫描开销
- 生成与写入合并为一个带互斥锁的后端事务，避免超时重试或多个 WebUI 并发写入
- 将自定义图标保存在可复用的修补组中；主题重新下载或 MRC 文件名变化后仍可选择原组修补
- “仅补全缺失图标”保留主题已有图标，“覆盖同名图标”优先使用修补组图标

## 注意

小米不同 HyperOS 版本可能改变活动主题路径、图标目录或主题刷新方式。
如果状态页无法识别当前主题，请提交 `ls -laZ /data/system/theme` 的脱敏输出。

模块仅使用“待修补主题”工作流，不再读取临时活动主题，也不再修复或导出 MTZ。

修补组与具体主题相互独立。重新下载主题后，只需加载新的 `.mrc`、选择原修补组和所需模式，再次执行修补。
